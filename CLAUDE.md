## Memory Bank (обязательно)

Курируемая база знаний проекта — `memory-bank/` (PARA: `projects/`/`areas/`/`resources/`/
`archive/`), индекс — `memory-bank/README.md`. В начале сессии индекс подгружается автоматически
(хук `SessionStart`) — перед задачей открой релевантную PARA-заметку (не всё подряд, `archive/`
по умолчанию не грузить). По завершении задачи обнови затронутые заметки: почти всегда
`memory-bank/projects/active-context.md` плюс один профильный (`resources/decisions.md` /
`projects/roadmap.md`). Без дублей — меняешь решение, правь существующий пункт. **Планируемая
(speckit-готовая, не начатая) фича — файл на фичу** в `memory-bank/projects/planned/NNN-slug.md`;
в `active-context` — строка-указатель; при влитии файл переезжает в `archive/`. Полный регламент
(Zettelkasten `[[links]]`, archive-on-completion, атомизация) — `memory-bank/README.md` и
[[memory-regimen]].

## Git-регламент: авто-завершение задачи (обязательно)

> **Единый источник** правил публикации. `/flow` и прочие процессы ссылаются сюда, не переписывая.
> Точные команды — `memory-bank/resources/commands.md` ([[commands]], раздел «Git-рецепты»).

**Триггер — запрошенная работа завершена** (тесты зелёные, открытых развилок нет). В `/flow`
это = **вся цель закрыта** (фича/долг/идея доведены), а НЕ каждая под-задача `Tnnn`. Незавершённую
цель в `develop` НЕ сливаем. По триггеру — **после** обновления Memory Bank — закоммитить, слить в
`develop` и запушить БЕЗ отдельного запроса (стоячая авторизация). Порядок:

1. **Отбор изменений — избирательно, НЕ `git add -A` вслепую.** Коммить ТОЛЬКО относящееся к
   задаче. В коммит не попадают: мусор/временные/scratch-файлы, всё из `.gitignore`, чужие
   несвязанные правки в рабочем дереве (в т.ч. в `stash`).
2. **Разделение по логике.** Несколько несвязанных тем — отдельные коммиты по смыслу. Сообщение —
   conventional-стиль, последней строкой `Co-Authored-By: <текущая модель> <noreply@anthropic.com>`
   (подпись даёт харнесс — не хардкодить модель).
3. **Тесты перед пушем.** Задача трогала код — прогнать релевантные тесты. Красные — НЕ пушить:
   доложить и остановиться.
4. **Ветки** (точные команды — [[commands]], «Git-рецепты»):
   - На `feat/NNN-*`: коммит на фиче → мерж в `develop` (`checkout` → `pull --ff-only` → `merge`
     → `push`); затем **обязательно удалить слитую ветку** (локально + `origin`) **и в ТОМ ЖЕ
     проходе провести уборку-по-мержу** (осиротевший worktree + устаревший код, который фича
     ретайрила/замещала). Замена = старое удаляется в её же завершении. Сомнение (код точно
     мёртв?) — не удалять наугад, вынести развилкой. Конфликт мержа → `git merge --abort`, СТОП,
     доложить.
   - На `develop`: коммит → `git push`.
   - **`main` автоматически НИКОГДА не трогаем** (мерж/пуш в `main` — только по явной команде).
5. **Промежуточный этап** (цель ещё не доведена — в т.ч. между под-задачами `Tnnn`) — авто-**мерж
   в `develop` пропустить**, НО **каждый коммит на своей ветке публикуется** (`git push`).
   Коммитит только оркестратор; mid-task субагенты/`flow-builder` НЕ коммитят.

**Старт работы на фиче-ветке — сначала синхронизация с `develop`** (рецепт в [[commands]]):
регламенты/агенты/банк (`.claude/*`, `memory-bank/`) живут на `develop` — без мержа `develop` в
фичу ветка работает по устаревшим правилам. Конфликт → `--abort`, СТОП, спросить.

## Рабочий процесс разработки (speckit)

Перед реализацией нетривиальной фичи — speckit-цикл, если `spec.md` ещё не написан:
`/speckit.specify` → `/speckit.clarify` → `/speckit.plan` → `/speckit.tasks` → `/speckit.analyze`
→ реализация по `tasks.md`. **`analyze` ОБЯЗАТЕЛЕН** (кросс-сверка `spec`↔`plan`↔`tasks`↔
конституция ДО реализации; находки применяются к артефактам, спорные — эскалируются). Реализация
начинается только с согласованных артефактов (0 CRITICAL/HIGH).

**Используй ГОТОВЫЕ команды** (`.claude/skills/speckit.*.md`). **Шаблоны артефактов бери ТОЛЬКО из
Memory Bank** — `memory-bank/resources/speckit-templates/` ([[speckit-templates]]), НЕ из
`.specify/templates/` (там generic-база).

**Когда speckit НЕ нужен:** баг-фикс, рефактор < 50 строк, правка конфига, обновление документации.
Полные детали — [[workflow]].

Активная фича — `.specify/feature.json` (`feature_directory`). Артефакты — `specs/<feature-name>/`.
По закрытии фичи `/publish` сбрасывает поле в `""` (нет активной фичи ⇔ `feature_directory=""`).
