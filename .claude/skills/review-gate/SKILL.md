## User Input

```text
$ARGUMENTS
```

Ты прогоняешь **ревью-гейт** на текущем рабочем диффе — до коммита.

## Шаги

1. **Выбери ревьюера ПО МАСШТАБУ диффа** (та же шкала «тривиально/нетривиально», что `/flow`
   применяет для speckit-skip — единое понятие «узкий/широкий» на весь сьют). Масштаб оценивай
   `git diff --stat` + сверкой путей с `.claude/code-analysis/architecture-zones.json`:
   - **Узкий** дифф (одна подсистема, нет попаданий в арх-зоны, ~<50 строк) → `/code-review`
     (дефолт `medium`) — быстрый одно-проходный.
   - **Широкий** (много подсистем / задевает арх-зоны / большой дифф) → `/ca-review` —
     cost-aware каскад команды flow (flow-router→finder→reviewer→[advocate]→[expert]): держит
     контекст оркестратора в бюджете там, где одно-проходный ревью раздул бы его.
2. Если дифф трогает чувствительное (auth/токены/секреты, публичный API, SQL/БД,
   внешние вызовы, отмена/конкурентность) — дополнительно прогони `/security-review`.
3. **Триаж находок**: тривиальные — почини сам (или раздай `flow-builder`) и перепроверь
   тесты; спорные или архитектурные — подними развилку пользователю, не решай сам.
4. Дальше идёт только принятый дифф (все триажированные находки закрыты или явно
   приняты пользователем).

**Дальше:** гейт пройден → `/publish` (если вызван отдельно от него) или продолжай
починку находок, если что-то осталось.
