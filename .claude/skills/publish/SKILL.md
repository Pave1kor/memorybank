## User Input

```text
$ARGUMENTS
```

Ты выполняешь процедуру **завершения и публикации**. Триггер — **вся цель доведена**
(фича реализована / долг починен / идея внедрена), тесты зелёные, открытых развилок
нет. НЕ вызывай это на каждой под-задаче `Tnnn` и НЕ при незакрытой цели — тогда просто
доложи статус и остановись (незавершённую цель в `develop` не сливай).

## Шаги

1. **Ревью-гейт.** Прогони `/review-gate` (code-review + при нужде security-review +
   триаж находок). Дальше идёт только принятый дифф — с гейтом, встроенным в этот шаг.
2. **Обнови Memory Bank на `develop`**: почти всегда `memory-bank/projects/active-context.md`
   плюс один профильный (`resources/decisions.md`/`projects/roadmap.md`;
   долг/идею — пометь `✅`, задачи в `tasks.md` — `[X]`). **Если менялись контракты/
   архитектура/слой данных или сами принципы** — в ТОМ ЖЕ завершении обнови И
   `CLAUDE.md`, И конституцию (`.specify/memory/constitution.md`): ни один из них не должен
   описывать удалённый/legacy-слой (правило синхронной актуализации). Меняешь принцип/раздел
   конституции — бампни её semver и Sync Impact Report (проще прогнать
   `speckit.constitution`). Перед этим свериться с принципами конституции проекта —
   комплаенс-ревью.
   - **Архивирование-по-завершении — ФАЙЛ НА ФИЧУ.** Если этот шаг закрывает фичу целиком:
     `memory-bank/projects/planned/NNN-slug.md` **переезжает** в
     `memory-bank/archive/features/NNN-slug.md` (перепиши как «закрыт»: суть/числа/merge sha),
     добавь строку в датированный индекс `archive/index.md`, а в `active-context.md` строку-
     указатель `[[NNN-slug]]` из планируемых убери и добавь ≤1 строку в «Недавно влитые».
     (Легаси-монолит `archive/closed-features.md` заморожен на 018–058 — в него НЕ дописывай.)
     Закрытый долг/идея → `archive/roadmap-closed.md` (или per-entity `projects/debts|ideas/*`
     переезжает в `archive/`), из `roadmap.md` убрать. Полный регламент — [[memory-regimen]].
     Прогони `python3 scripts/check_memory_links.py` после переноса (ссылки + сирот-проверка).
   - **Сброс активной фичи (если закрывается фича).** Если слитая цель — speckit-фича, то
     после мержа её ветки в `develop` сбрось `.specify/feature.json` →
     `{ "feature_directory": "" }`: иначе поле продолжит указывать на уже влитую фичу, и
     `/status`, а также setup-скрипты speckit (`setup-plan`/`setup-tasks`/
     `check-prerequisites`) увидят ложную «активную» фичу. В ТОМ ЖЕ проходе убери запись
     этой фичи из секций `active-context.md` про планируемое/в работе (напр.
     «Запланированные фичи») — оставь только однострочную выжимку «влита». Артефакт и
     заметка должны сходиться: нет активной фичи ⇔ `feature_directory=""` и ни одна фича
     не числится «в работе/запланирована».
3. **Коммит → мерж `feat`→`develop` → пуш → удалить слитую ветку → уборка-по-мержу** —
   точные команды в каталоге [[commands]] («Git-рецепты»): избирательный коммит без
   мусора/«корзины» → `feat/NNN` → `checkout develop` → `pull --ff-only` → `merge` →
   `push`, затем **обязательно удалить слитую ветку** (локально + на `origin`) **и в ТОМ ЖЕ
   проходе провести уборку-по-мержу** (рецепт «Уборка-по-мержу»): прибрать осиротевший
   worktree слитой фичи (`git worktree remove` + `prune`) И удалить устаревший код, который
   фича ретайрила/замещала (мёртвые модули/блоки, замещённые файлы, пустые `__pycache__`
   ретайренных блоков) — замена удаляет старое в её же завершении, долг-«уборка» не
   заводится; сомнение (код точно мёртв?) — не удалять наугад, вынести развилкой. Конфликт
   слияния — **СТОП**, спроси пользователя, не разрешай наугад; `main` не трогаем; прямо на
   `develop` — просто коммит + `push origin develop`.
4. **Сессионная очистка.** Цель закрыта = сильная граница сессии: durable-знание уже
   в банке (шаг 2), поэтому убери эфемерное — регенерируемые кэши/логи прогонов
   (`.claude/code-analysis/*.json`, `memory-bank/.recall-index.json`, session-scratch).
   Durable (`memory-bank/**`, `.claude/agents|skills`, `specs/**`) не трогай. Если в проекте
   есть свой скрипт очистки — используй его; иначе `/checkpoint` делает то же на границе пачки.
5. **Доложи**: что сделано, статус тестов, итог ревью (что нашли/починили), что слито и
   запушено.

Мерж `feat`→`develop` делается **только по этому триггеру** (незавершённую цель в
`develop` не сливаем). НО каждый коммит публикуется сразу — любой коммит (промежуточный
на фиче-ветке, записи банка/roadmap на `develop`) сразу пушится на свою ветку
(правило публикации). Коммитит только оркестратор/этот скилл; mid-task субагенты/
`flow-builder` не коммитят.

**Дальше:** цель закрыта — жди пользователя (новая цель через `flow <описание>` или
`flow new <описание>`).
